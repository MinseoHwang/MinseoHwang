# 넥서스원 반도체 검사 AI 개발

[프로필로 돌아가기](../README.md)

웨이퍼 결함 분류 모델을 실험하고, 추론 결과를 C++/MFC 검사 프로그램에서 활용하도록 연결했습니다. 학습 데이터의 불균형, 기존 검사 정보의 보존, 추론 호출 시간을 각각의 문제로 나누어 다뤘습니다.

## 클래스 불균형에 대응한 분류 실험

결함 클래스별 데이터 수가 달라 클래스별 분류 양상을 확인할 필요가 있었습니다. 이미지·라벨 정리와 중복 이미지 탐색, crop·letterbox·색상 정규화를 다루고, 클래스 가중치·WeightedRandomSampler·Focal Loss·증강 방법을 실험했습니다.

전이학습 모델을 비교하면서 클래스별 결과와 CAM을 확인했습니다. 정제 전후 평가의 데이터 구성이 달라 동일한 고정 테스트셋에서 얻은 개선률로 제시하지 않습니다.

## 기존 검사 정보를 보존하는 추론 연동

모델의 결과만 별도로 저장하면 기존 검사 정보와 함께 활용하기 어렵습니다. 클라이언트가 전달한 CSV·이미지 경로를 받아 배치 추론하고, 기존 CSV 메타데이터에 분류 결과와 확률을 추가하는 흐름을 다뤘습니다.

```text
검사 프로그램 → CSV·이미지 경로 전달 → 전처리·배치 추론
                                      ↓
                   기존 CSV 정보 유지 + 분류 결과·확률 기록
```

ONNX Runtime을 C++/MFC 프로그램에 연결하고 CPU·GPU 추론 호출을 연동했습니다. 모델의 logits를 확률과 구분해 처리하고, 결과 기록 과정에서 기존 검사 정보가 유지되도록 구성했습니다.

## 모델 형식별 추론 호출 시간 비교

추론 호출 시간을 줄이기 위해 PyTorch 모델을 ONNX와 TensorRT FP16으로 변환해 비교했습니다. 내부 실험 기록의 이미지당 평균 호출 시간은 다음과 같습니다.

| 모델 실행 형식 | 평균 추론 호출 시간 |
| --- | ---: |
| PyTorch | 6.222ms |
| ONNX | 4.279ms |
| TensorRT FP16 | 1.916ms |

이는 특정 실험 환경의 호출 시간입니다. CSV 입출력·전처리·통신을 포함한 장비 전체 처리시간이나, 형식 변환 후 정확도의 동등성을 입증하는 결과는 아닙니다.

## 구현 범위

모델 실험·프로그램 연동·호출 시간 비교를 다뤘습니다. 회사 소스와 원본 이미지는 공개하지 않으며, 모든 실험 모델의 양산 적용이나 고객 검수 완료로 확대해 설명하지 않습니다.
