# FinAudit 답변의 인용과 소수 수치 검증

[FinAudit 개요](README.md) · [원본 변경 PR #57](https://github.com/kt-aivle-big-project-13/ai-repo/pull/57)

## 문제

감사 챗봇에서 “임계값을 0.5로 바꾸면?”이라는 질문에 재계산할 수 없다고 답했지만, 답변의 근거 상태가 `PARTIAL`로 표시됐습니다. 답변에 포함된 `0.5`가 감사 근거에는 없었기 때문입니다. 사용자의 질문에서 가져온 값을 검증 로직이 근거 없는 수치로 취급한 오탐이었습니다.

## 변경과 이유

답변의 소수를 대조할 때 감사 근거뿐 아니라 질문도 확인하도록 수정했습니다. 질문에 나온 값을 언급하는 것과 모델이 새로운 수치를 생성하는 것을 구분하기 위해서입니다. 같은 질문이 다시 들어왔을 때 오탐이 발생하지 않도록 회귀 테스트를 추가했습니다.

인용은 번호가 붙은 근거 블록을 기준으로 파싱하고, 응답에는 실제 인용한 항목만 반환했습니다. 전체 근거를 모두 인용 목록에 넣으면 답변이 어떤 자료를 사용했는지 알기 어렵기 때문입니다.

## 응답 판정

| 조건 | 동작 |
| --- | --- |
| 주입할 근거가 없음 | LLM을 호출하지 않고 `NOT_GROUNDED` 반환 |
| 인용이 없거나 답변의 소수가 근거·질문에 없음 | `PARTIAL`로 표시 |
| 검증 조건 충족 | `GROUNDED`로 표시하고 실제 인용 목록 반환 |

정수는 연도·장 번호·항목 개수로 자주 나타나므로 수치 검사에서 제외했습니다. 이 선택은 오탐을 줄이지만 정수 수치 오류를 검사하지 못하는 한계도 남깁니다.

## 검증

PR의 단위 테스트는 LLM 응답을 가정해 다음 분기를 검사합니다.

- 질문에서 온 소수는 허용하고, 근거·질문 어디에도 없는 소수는 `PARTIAL`로 표시.
- 인용 번호의 중복·존재 여부와 실제 인용한 근거만 반환하는 동작 확인.
- 근거가 없으면 모델 호출을 생략하는지 확인.

[MinseoHwang 작성·병합 PR #57](https://github.com/kt-aivle-big-project-13/ai-repo/pull/57)에서 변경을 확인할 수 있습니다. 테스트는 검증 로직의 분기를 확인하며, 환각 발생률이나 답변 전체의 사실성을 측정한 결과는 아닙니다.

## 한계와 개선 방향

`GROUNDED`는 구현한 규칙을 통과했다는 뜻입니다. 질문에 잘못된 수치가 들어 있거나, 인용한 문서와 답변의 의미가 어긋나는 문제까지 판정하지는 않습니다. 다음 평가에서는 인용의 의미 일치, 잘못된 질문 전제, 정수 수치를 별도 사례로 다룰 수 있습니다.
