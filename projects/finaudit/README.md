[프로필로 돌아가기](../../README.md)

## 서비스와 담당 범위

팀 서비스는 분석·보고서·감사 이력·질의응답을 제공합니다. 아래는 그중 이 문서에서 설명하는 연동 흐름입니다.

```text
감사 요청 → Spring 백엔드 → FastAPI 분석 → 분석 결과
                 │                          │
                 │                    보고서 생성·S3 저장
                 │
질문 ────────────┴→ 지표·법령·보고서 근거 → 답변 생성 → 인용·수치 검증
```

기존 SHAP 분석 API는 팀원이 구현했습니다. 제가 확장한 부분은 보고서 payload·S3 저장 연동, 감사 챗봇의 검증, 분석·보고서 실행 제어 등입니다.

## 보고서 연동과 협업

팀원의 분석 API 위에 보고서에 필요한 payload와 S3 저장을 확장했습니다. 기존 호출자가 받던 분석 응답을 유지하고, 저장 실패가 분석 결과를 잃는 원인이 되지 않도록 처리했습니다. 이후에는 S3에 있는 SHAP 결과를 재사용하고 조회 실패 시 다시 계산하는 경로를 추가했습니다. [PR #93](https://github.com/kt-aivle-big-project-13/ai-repo/pull/93)

법령 검색은 pgvector 기반 유사도 검색과 검색 실패 격리를 다뤘습니다. 챗봇이 사용할 수 있는 근거를 연결하는 역할이며, 법령 해석의 정확성이나 규제 준수 자체를 보장하는 기능은 아닙니다. [백엔드 PR #202](https://github.com/kt-aivle-big-project-13/backend-repo/pull/202)

## 검증과 남은 과제

- 답변 검증은 LLM 응답을 가정한 단위 테스트로 인용·수치 판정 분기를 확인했습니다. 실제 LLM 품질 평가와 구분합니다.
- 실행 제한은 허용량 초과, 대기 초과, 예외 후 슬롯 반환, HTTP 상태 매핑을 다룬 테스트 기록이 있습니다.
- 배포 환경에서의 처리 지연·메모리 개선률과 상용 트래픽 성과는 이 문서의 검증 범위가 아닙니다.

테스트 설명은 해당 PR과 보관된 검증 기록 기준입니다. 2026.11.05 문서 작성 중 애플리케이션 테스트를 다시 실행하지 않았습니다.
