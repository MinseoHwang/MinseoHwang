# Melpik | 의류 대여 이용권과 상품 데이터 처리

[프로필로 돌아가기](../../README.md)

의류 대여 서비스 참여 경험입니다. 이용권 차감·취소 복원과 상품 수집·검수 적재를 다룹니다. 아래 내용은 2026.11.04 확인한 프로젝트 구현이며, 후속 로컬 변경 전체를 개인 단독 기여로 제시하지 않습니다. 소스는 비공개입니다.

**기술:** TypeScript, NestJS, TypeORM, MySQL, Python, Playwright, SQLite.

## 이용권 취소 복원

마지막 회차를 사용한 예약을 취소할 때 횟수 소진·수동 종료·만료를 구분해야 합니다. 사용한 이용권과 차감 묶음을 기록하고, 취소 시 잔여 회차·유효기간·종료 기록을 함께 확인해 복원 대상을 판단합니다. 취소 완료 여부를 검사해 같은 요청에서 회차를 반복 복원하지 않도록 처리합니다.

## 중단 후 이어 가는 상품 수집

4개 의류 사이트의 수집 작업을 SQLite에 저장하고, 중단 후 완료 작업을 보존한 채 이어 갑니다. 목록에서 발견한 상세 작업과 목록 완료를 함께 저장하며, 반복 오류와 식별 충돌 데이터는 검토 대상으로 분리합니다.

브랜드·품번·색상 기준 식별과 사진 검수 정책을 거쳐 상품을 적재합니다. 수집 성공과 등록 가능 여부를 별도 단계로 다룬다는 점이 핵심입니다.

## 검증 기록

| 항목 | 확인 결과 |
| --- | --- |
| 2026.11.04 크롤러 테스트 | 원본 58개 통과, 보관용 사본에서도 같은 58개 통과 |
| 백엔드 선별 테스트 | 83개 중 82개 통과, 1개 실패 |
| 관리자 실측·소재 화면 | 9개 통과 |
| 과거 상품 등록 검증 기록 | 2026년 가을·겨울 대상 1,412건 검증, 현재 운영 DB 재집계 아님 |

백엔드 실패 1건은 구독 첫 결제 거절 뒤의 상태에 관한 테스트와 구현의 차이입니다. 테스트는 결제 대기를 기대하지만 구현은 취소·재고 복구로 처리합니다. 정책을 확인한 뒤 양쪽을 맞추는 작업이 남아 있습니다.

수집 기록은 규칙 모드·모델 호출 0회이며, 전체 수집 상태는 `REVIEW_REQUIRED`였습니다. 상품 등록 검증 건수는 결제 거래량이나 서비스 전체 상용화 실적이 아닙니다.
